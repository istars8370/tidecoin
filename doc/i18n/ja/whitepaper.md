# Tidecoin：耐量子安全なピアツーピア暗号資産

**原文：Tidecoin ホワイトペーパー v2.0 — 2026年2月**

> **非公式コミュニティ翻訳の草稿です。** 要旨および第1～3章のみを翻訳しています。技術的な判断には[英語原文](../whitepaper.md)を参照してください。

## 要旨

Tidecoinは、従来型コンピューターと量子コンピューターの双方による攻撃への耐性を、ジェネシスブロックから考慮して設計された分散型暗号資産である。Bitcoin Coreを基盤とし、UTXOモデル、スクリプトシステム、長年検証されてきたコンセンサスロジックを維持しながら、ECDSAをNISTの耐量子暗号（PQC）標準化プロセスで選定されたFalcon-512/1024およびML-DSA-44/65/87署名方式に置き換える。署名以外にも、強化導出のみを認めるPQHDウォレット、SHA-512のウィットネススクリプト、ML-KEM-512によるP2P通信暗号化、CPU向けYespowerTIDEからLitecoinとのscryptマージマイニングへ移行する二段階のプルーフ・オブ・ワーク戦略を含む。ネットワークは2020年12月27日から運用されている。

## 1. はじめに

現在の暗号資産の多くは、楕円曲線離散対数問題（ECDLP）の計算困難性に安全性を依存している。BitcoinやEthereumなどでは、secp256k1曲線を用いたECDSAまたはSchnorr署名が使われる。Peter Shorは1994年、離散対数問題を量子コンピューター上で多項式時間で解くアルゴリズムを示した。十分に強力な量子コンピューターが実現すれば、公開鍵から対応するECDSA秘密鍵を導出できる可能性がある。

米国国立標準技術研究所（NIST）は2016年にPQC標準化を開始し、2022年に最初のアルゴリズムを選定、2024年8月にFIPS 203・204・205を公開した。NIST IR 8547は耐量子暗号への移行スケジュールを示している。米国連邦準備制度も2025年に分散型台帳に対する「今収集し、後で復号する」脅威を検討した。

Tidecoinはこうしたリスクへの対応を目的として考案された。2020年12月27日のジェネシスブロックには、光量子コンピューターによる量子計算上の優位性を報じたIEEE Spectrumの記事見出しが刻まれている。これは中国科学技術大学の光量子コンピューター「九章（Jiuzhang）」の実験に言及するものだ。

原文では、5年以上の稼働、230万以上のブロック生成、報告されたセキュリティ事故・合意障害・暗号学的脆弱性がないことを述べている。これらの運用実績は独立した検証が必要である。

## 2. 暗号資産に対する量子の脅威

### 2.1 ShorのアルゴリズムとECDSA

Shorのアルゴリズムは、量子コンピューターでECDLPを多項式時間で解く。原文はsecp256k1に対する古典的攻撃を約2^128回の演算、量子攻撃に必要な資源を約2,500論理量子ビット、特定の誤り訂正の仮定の下で約10^5～10^6物理量子ビットと見積もる。これらは攻撃モデルに依存する推定値である。

### 2.2 「今収集し、後で復号する」問題

ブロックチェーンのデータは公開され、改変が困難である。攻撃者は現在公開されている取引や公開鍵を保存し、将来十分な量子計算能力を得た時点で攻撃を試みることができる。原文はBitcoinにおける公開鍵の露出やアドレス再利用のリスクを扱う。影響を受ける資産量の推計は時点と分析手法に左右される。

### 2.3 移行が難しい理由

既存チェーンの耐量子移行には、コミュニティの合意形成、署名サイズ増大によるブロック容量の負担、移行不能な古い資産、アップグレード時期の調整などの課題がある。Tidecoinはジェネシスから耐量子署名を採用する方針を選んだ。

## 3. 設計思想

### 3.1 実験的手法よりNIST標準を優先

ML-DSA（FIPS 204）、ML-KEM（FIPS 203）、Falcon（FIPS 206草案）、SHA-512（FIPS 180-4）など、標準化済みまたはNISTの選定プロセスを経た暗号技術を中心に構成する。**標準化、コード実装、メインネットでの有効化は別の状態である。**

### 3.2 再発明ではなくBitcoinの基盤を継承

Bitcoin CoreのUTXOモデル、スクリプト、P2Pネットワーク、ブロック伝播、メモリプールの構造を維持し、量子セキュリティに必要な部分を拡張する。

### 3.3 多層防御

| レイヤー | 従来のBitcoin系方式 | Tidecoin白書の設計 |
|---|---|---|
| 取引署名 | ECDSA | Falcon-512/1024、ML-DSA-44/65/87 |
| ウィットネススクリプトのハッシュ | SHA-256 | SHA-512 |
| P2P通信 | ECDH | ML-KEM-512 |
| プルーフ・オブ・ワーク | SHA-256d | YespowerTIDE → scryptマージマイニング |
| 階層的ウォレット | BIP32 | 強化導出専用PQHD |

### 3.4 慎重な有効化

Falcon-512はジェネシスから使用され、追加署名方式は指定されたブロック高でコンセンサスアップグレードにより有効化する設計である。**設計・実装・メインネット有効化を混同してはならない。**
